## BLOCKERS — Fix Before Any New Features

### BUG-01 · `processingStartedAt` migration not run
**File:** `app/api/n8n/queue/route.ts` — has a try/catch fallback for when the column doesn't exist  
**Impact:** `retry_count` tracking silently fails. Chronically-failing queue items can loop forever with no visibility. Stuck detection falls back to the less-accurate `ingestedAt` timestamp.  
**Fix:** Hit `POST /api/admin/db/migrate-ingested-content` once in production.  

### BUG-02 · `/api/tip` loses all submitted tips
**File:** `app/api/tip/route.ts`  
**Impact:** Every reader tip goes to `console.log` — ephemeral on Vercel, gone in seconds. Zero tips have ever been saved.  
**Fix:** Insert into a `tips` DB table (schema needed) or integrate Resend email. The commented-out Resend block is already there — wire it up.

### BUG-03 · `NEXT_PUBLIC_AUTOMATION_API_KEY` in client bundle
**File:** `.env.local` + Vercel dashboard  
**Impact:** The `NEXT_PUBLIC_` prefix bakes this key into the browser JavaScript bundle. Any visitor can open DevTools → Sources and find `camer360_auto_42756d753611bdfb3c08ab2714cae872`. That key authenticates all n8n API endpoints including `/api/n8n/ingest` (inject content) and `/api/n8n/health?reset=1` (reset queue).  
**Fix:** Remove `NEXT_PUBLIC_AUTOMATION_API_KEY` from Vercel env vars. Keep only `AUTOMATION_API_KEY`. The code already prefers `AUTOMATION_API_KEY` via `?? NEXT_PUBLIC_AUTOMATION_API_KEY` fallback — removing the public variant is safe.

## SECURITY ISSUES

### SEC-01 · No `middleware.ts` — zero edge protection
**Impact:** Admin route protection lives only in `app/admin/(protected)/layout.tsx`, which is a server component. There is no Next.js middleware intercepting requests at the edge. Direct requests to admin API routes (e.g. `PATCH /api/admin/articles/[id]`) are only blocked if the route handler itself checks auth — and not all do consistently.  
**Fix:** Add `middleware.ts` at project root to protect `/admin/*` at the edge. Example:
```ts
import { NextRequest, NextResponse } from 'next/server'
import { verifyToken } from '@/lib/auth'

export async function middleware(req: NextRequest) {
  if (req.nextUrl.pathname.startsWith('/admin') && 
      !req.nextUrl.pathname.startsWith('/admin/login')) {
    const token = req.cookies.get('admin_token')?.value
    if (!token) return NextResponse.redirect(new URL('/admin/login', req.url))
    const payload = await verifyToken(token)
    if (!payload) return NextResponse.redirect(new URL('/admin/login', req.url))
  }
  return NextResponse.next()
}

export const config = { matcher: ['/admin/:path*'] }
```

### SEC-02 · No rate limiting on any public API
**Affected endpoints:** `/api/comments`, `/api/newsletter`, `/api/reactions`, `/api/hit`, `/api/tip`, `/api/search`, `/api/polls`  
**Impact:** Unbounded POST spam. Comment flood, newsletter subscription bombing, reaction manipulation, hit counter stuffing.  
**Fix:** Implement IP-based rate limiting via Vercel's built-in Edge Config + `@vercel/kv`, or add simple in-memory throttle per IP using a LRU map in middleware.

### SEC-03 · No HTTP security headers
**File:** `next.config.ts` — no `headers()` config exists  
**Missing headers:** `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Content-Security-Policy`  
**Impact:** Site can be iframed (clickjacking), MIME-sniffing enabled, referrer leaks.  
**Fix:** Add to `next.config.ts`:
```ts
async headers() {
  return [{
    source: '/(.*)',
    headers: [
      { key: 'X-Frame-Options', value: 'SAMEORIGIN' },
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
      { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
    ],
  }]
}
```

### SEC-04 · SSL cert verification disabled on DB connection
**File:** `lib/db/client.ts` line 16 — `ssl: { rejectUnauthorized: false }`  
**Impact:** Accepts any TLS certificate from the DB host. Vulnerable to MITM on the DB connection. Low risk in practice (Hostinger managed hosting), but bad practice.  
**Fix:** Set `ssl: { rejectUnauthorized: true }` and ensure Hostinger's CA cert is trusted, or remove the ssl option if the connection is internal.

### SEC-05 · Old-project fallback password in auth route
**File:** `app/api/admin/auth/login/route.ts` line 5  
**Code:** `const ADMIN_PASS = process.env.ADMIN_PASSWORD || 'concord2026admin'`  
**Impact:** If `ADMIN_PASSWORD` is ever missing from Vercel env, `concord2026admin` becomes the live admin password. Also reveals the old project codename.  
**Fix:** Remove the fallback. Throw an error if the env var is missing:
```ts
const ADMIN_PASS = process.env.ADMIN_PASSWORD
if (!ADMIN_PASS) throw new Error('ADMIN_PASSWORD env var not set')
```

### SEC-06 · No file type validation in upload route
**File:** `app/api/admin/upload/route.ts`  
**Impact:** Any file can be submitted. Sharp will throw for non-images, but the raw error leaks to the response. No explicit MIME type allowlist.  
**Fix:** Add before processing:
```ts
const ALLOWED_TYPES = ['image/jpeg', 'image/png', 'image/gif', 'image/webp', 'image/avif']
if (!ALLOWED_TYPES.includes(file.type)) {
  return NextResponse.json({ error: 'File type not allowed' }, { status: 400 })
}
```

## PERFORMANCE

### PERF-01 · `images.unoptimized: true` kills frontend image optimization
**File:** `next.config.ts` line 4  
**Impact:** Next.js `<Image>` component serves images at full original resolution with no WebP conversion, no responsive srcset, no lazy loading optimizations. Every page load pulls full-size images.  
**Note:** Upload route already converts to WebP via sharp (correct). The issue is the `next.config.ts` flag disabling the frontend serving pipeline.  
**Fix:** Remove `unoptimized: true`. If Vercel's image optimization causes issues with R2 URLs, use `remotePatterns` instead:
```ts
images: {
  remotePatterns: [{ hostname: 'media.camer360.com' }],
}
```

### PERF-02 · DB connection pool vs Vercel serverless
**File:** `lib/db/client.ts` — `connectionLimit: 10`  
**Impact:** Each Vercel serverless instance creates a new pool of 10. Under concurrent traffic (e.g. homepage rendering 5 parallel RSC calls + n8n hitting the API), Hostinger's MySQL can be hit with 10×N connections. Hostinger shared hosting plans have low connection limits.  
**Fix:** Drop `connectionLimit` to 3-5. Add `waitForConnections: true` (already set) and monitor via health endpoint.
